# 提修改

## 核心原则：**给现象，不给评价**

| ❌ 别这么说 | ✅ 这么说 |
|---|---|
| "不好看" | "标题字号从 16px 调到 24px，颜色改成 #333" |
| "不好玩" | "第一关太难，前 3 波敌人从 5 个减到 2 个" |
| "有 bug" | "点开始按钮后没反应，控制台报 `xxx is not defined`" |
| "再改改" | "把结算面板从右侧移到屏幕正中间" |
| "太慢了" | "列表加载超过 3 秒，数据有 200 条" |

## 万能模板

```
【哪里】______（哪个页面/哪个元素）
【现在】______（客观描述当前状态）
【想要】______（具体目标，带数字）
```

## 一次只改一件事

**这是代价最高的一条。**

```
❌ 顺便把这些也改一下：字号大点、颜色深点、
    按钮圆角、加个动画、列表改成两列

✅ 先把标题字号改大。改完我看看。
```

连提 5 个要求 → 5 个都可能改歪，而且你分不清是哪个改动导致的问题。

## 不知道该怎么描述时

```
我想改 ______，但说不清楚具体要什么。
请你先给我 3 个具体方案（带描述），我选一个，你再动手。
```

## 改之前先让它说方案

**大改动前必做**，能省很多返工：

```
这个改动比较大。请先告诉我你打算怎么改，
包括会动哪些文件、可能影响什么。我确认了你再动手。
```
