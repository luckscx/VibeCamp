# 模板 · 极简记账本

> ⚠️ **状态：草稿**。提示词尚未实机跑通，请以实际结果为准。

## 一句话描述

一个网页版记账本：记一笔（分类 + 金额 + 备注）、看本月列表和总额、能删记错的。数据存浏览器本地。

## 为什么它是"小应用"的最佳入门

它把「要不要登录 / 数据存哪」这两个**决定工作量量级**的问题暴露得特别清楚：

| 你的回答 | 工作量 |
|---|---|
| 只存本地、不要登录 | 一个 HTML 文件，一小时能跑 |
| 要登录、要多设备同步 | 后端 + 数据库 + 服务器，几天起步 |

所以这个模板的提示词里，**"明确不要的"比"必须有的"更值钱**。

## 完整需求

```markdown
# 极简记账本

## 一句话
我要做一个记账网页，用来记录每天的开销。

## 给谁用
我自己一个人用。

## 怎么用
1. 打开页面，看到上半部分是"记一笔"表单，下半部分是本月流水列表
2. 我选分类（餐饮/交通/购物/其他）、填金额、写备注，点"保存"
3. 这条记录出现在下面的列表里，顶部的"本月合计"同步更新
4. 每条记录右边有个删除按钮，点一下就删掉

## 必须有的功能
1. 记一笔：分类下拉 + 金额输入 + 备注（可空）+ 保存按钮
2. 本月流水列表，按时间倒序（最新的在上面）
3. 顶部显示本月合计金额
4. 每条记录能删除
5. 数据存浏览器本地，关掉浏览器再打开还在

## 明确不要的
1. 不要登录注册、不要用户系统
2. 不要云端同步、不要多设备
3. 不要预算提醒、不要超支提醒
4. 不要图表统计、不要饼图柱状图
5. 不要手机 App，只要网页
6. 不要导出 CSV（第一版不做）
7. 不要编辑已记录的条目（第一版只能删了重记）

## 风格参考
- 白底 #ffffff，大留白，圆角卡片
- 主色蓝 #2563eb，文字 #333，不要用纯黑
- 参考微信读书的清爽感：少线条、多留白

## 技术偏好
- 单个 HTML 文件（或你决定，但要告诉我怎么打开）
- 数据存 localStorage
- 前端框架你决定，我是零基础
```

## 建议的第一句话

```markdown
我要做一个极简记账网页，完整需求见上。

在动手之前，请先问我 5 个问题，重点确认：
- 我列的"明确不要的"里，有没有你觉得不做会导致明显问题的
- 数据存 localStorage 具体怎么组织（存成什么结构）
- 有哪些我没想到的坑

一次问完，我逐条回答。问完等我确认再开始写代码。

代码要求：
- 用中文注释解释每段在干什么
- 我是零基础，不要引入需要命令行构建才能跑的方案
  （我要的是"双击就能用"，不是"先 npm install 再 npm run build"）

做完请告诉我：
1. 怎么打开
2. 我该看到什么
3. 哪些功能现在能试
4. 我做哪几步操作，能验证数据真的存下来了
```

## 验收点

- [ ] 打开页面能看到"记一笔"表单和下面的列表区
- [ ] 记一笔（餐饮 / 38.5 / 午饭），保存后出现在列表**最上面**
- [ ] 顶部的本月合计**立刻**变成 38.5（不用刷新页面）
- [ ] 再记一笔，合计变成两笔之和
- [ ] 点某条记录的删除按钮，它消失，合计同步减少
- [ ] **关掉浏览器，重新打开**，刚才记的数据还在
- [ ] 金额输入字母或留空时，不会把页面搞崩（哪怕提示不好看也行，先别崩）

> 最后一条是新手最容易忽略的。AI 写的代码通常只处理"正常输入"，
> 你在金额框里打个 `abc` 试试 —— 如果页面直接白屏，回去找它修。

## 做完之后还能加什么

一次加一个，每加一个都重新验收：

1. 编辑已记录的条目
2. 按月筛选（切换月份看不同月份的数据）
3. 分类统计（每个分类花了多少）
4. 导出 CSV
5. 简单的柱状图

## 这个模板教了什么

- **"不要登录"这五个字，省掉了整个后端** —— 这不是偷懒，是 MVP 思维：
  先做一个能用的，用起来之后你才知道真正缺什么
- **"双击就能用"是一句关键约束** —— 不说的话，AI 很可能给你一套
  Vite + React 的工程，你连怎么启动都不知道
