# 模板 · 2048

> ⚠️ **状态：草稿**。提示词尚未实机跑通，请以实际结果为准。

## 一句话描述

4×4 棋盘，方向键滑动合并相同数字，每次移动后随机出现一个 2 或 4，目标是凑出 2048。

## 为什么它比贪吃蛇难一档

贪吃蛇的逻辑是「画出来就行」，2048 的逻辑是**数据先于画面**：

- 移动合并的规则藏在数组操作里
- 「一次移动中每个格子只能合并一次」—— 这条规矩最容易写错
- 画面只是数据的一种展示方式

所以这个模板的提示词特意要求**分两步做**，先跑通逻辑再画画面。

## 完整需求

```markdown
# 2048

## 一句话
我要做一个 2048 游戏，用方向键合并数字。

## 给谁用
我自己。

## 怎么用
1. 打开页面，看到 4×4 的棋盘，其中两格有数字（2 或 4）
2. 我按方向键，所有数字块朝那个方向滑动到底
3. 相同的数字碰到一起会合并成它们的和，每个数字每次移动只合并一次
4. 每次有效移动后，随机空格生成一个新数字（90% 是 2，10% 是 4）
5. 棋盘满了且四个方向都无法移动时，游戏结束

## 必须有的功能
1. 4×4 棋盘，方向键滑动
2. 相同数字合并，每次移动每格只合并一次
3. 每次移动后随机生成新数字
4. 显示当前分数（每次合并加上合并后的数字）
5. 支持撤销上一步
6. 最高分存本地

## 明确不要的
1. 不要动画做得太花（先能玩，动画后面再加）
2. 不要登录、排行榜
3. 不要手机触屏（第一版只做键盘）
4. 不要 5×5 / 6×6 可切换（先固定 4×4）

## 风格参考
- 米色背景 #faf8ef，棋盘 #bbada0，空格 #cdc1b4
- 数字块的配色参考原版 2048（2 是米白、4 是淡黄、8 是橙色……）

## 技术偏好
- 单个 HTML 文件
- 你决定内部怎么组织，但请先把合并逻辑单独实现并验证
```

## 建议的第一句话

```markdown
我要做一个 2048 游戏，需求见上。

请分两步做，不要一次做完：

【第一步】只做数据逻辑，不做画面：
- 用一个 4×4 的二维数组表示棋盘
- 实现上下左右四个方向的移动与合并
- 关键规则：一次移动中，每个格子最多参与一次合并
  （例如 [2,2,2,2] 向左移动应该变成 [4,4,0,0]，而不是 [8,0,0,0]）
- 每次有效移动后，在随机空格生成 2（90%）或 4（10%）
- 无法移动时判定游戏结束
- 写完后用 console.log 打印几个测试用例验证：
  [2,2,2,2] 左移 → [4,4,0,0]
  [4,2,2,4] 左移 → [4,4,4,0]
  [2,2,4,0] 左移 → [4,4,0,0]
- 把验证结果贴给我，我确认了再做第二步

【第二步】再做画面：
- 用 CSS 或 Canvas 渲染棋盘
- 数字块滑动加个位移动画
- 不同数字不同颜色
- 显示当前分数、最高分
- 加一个"撤销"按钮

我是零基础，关键逻辑请写中文注释。
每步做完告诉我该看到什么、怎么验证。
```

## 验收点

**第一步（逻辑）**：

- [ ] AI 贴出了测试用例的实际输出
- [ ] `[2,2,2,2]` 左移结果是 `[4,4,0,0]`（不是 `[8,0,0,0]`）
- [ ] `[4,2,2,4]` 左移结果是 `[4,4,4,0]`

**第二步（画面）**：

- [ ] 打开能看到 4×4 棋盘，初始有两个数字
- [ ] 按方向键，数字块滑动并合并
- [ ] 分数会随合并增加，加的是**合并后的数字**（2+2 合成 4，加 4 分）
- [ ] 撤销按钮能退回上一步（棋盘和分数都退）
- [ ] 关掉再打开，最高分还在
- [ ] **连续按同一个方向**，如果这一行没变化，不应该生成新数字

> 最后一条是 2048 最经典的隐藏 bug。很多实现里，按了一个「什么都没动」的方向，
> 也会生成一个新数字，玩起来会觉得"数字冒得特别快"。

## 这个模板教了什么

- **「先逻辑后画面」是复杂功能的通用拆法** —— 逻辑对了画面只是皮，
  逻辑错了画面再漂亮也白搭，而且你很难从画面上看出逻辑错在哪
- **给测试用例就是在给验收标准** —— 你在提示词里写了 `[2,2,2,2] → [4,4,0,0]`，
  AI 就知道你在意"每格只合并一次"，它会专门处理这个边界
