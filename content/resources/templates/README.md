# 项目模板库

> 抄作业用。每个模板给出：需求描述（可直接粘给 AI）+ 建议的第一句话 + 验收点。

## ⚠️ 先读这段：模板的状态是什么意思

| 标记 | 意思 | 你能信到什么程度 |
|---|---|---|
| ✅ **已跑通** | 有人真的按这个提示词做出来过，验收点全过 | 可以直接抄，改动很小 |
| 🚧 **草稿** | 提示词按本训练营的方法论写过，但**还没实机跑过** | 当作起点，第一次跑可能要改几轮 |

**目前全部是 🚧 草稿。** 我们不假装跑过 —— 宁可告诉你"这个没验证"，
也不让你以为抄下去就该一次成功。

> 这正是本训练营的核心观点之一：**AI 说"做完了"不等于真的做完了**（见第 0 章示例 2）。
> 我们对自己的内容也用同一条标准。
>
> 如果你按某个模板跑通了，欢迎回来把它标成 ✅ 并附上你的改动 —— 见文末「怎么贡献」。

## 模板格式（统一）

每个模板文件按这个结构写：

```markdown
## 一句话描述
（可直接粘给 AI 的那句话）

## 完整需求
（填好的需求模板）

## 建议的第一句话
（粘给 AI 的开头，含反向追问）

## 验收点
- [ ] ...

## 这个模板教了什么
（抽象成通用教训，换个项目也适用）
```

## 怎么用这些模板

1. **别直接全抄** —— 把"完整需求"里的分类、颜色、习惯名改成你自己的
2. **"明确不要的"别删** —— 那是模板里最值钱的部分，删了 AI 就会做多
3. **照着验收点逐条走** —— 有任何一条不过，回去按第 4 章的方式提修改
4. **一次只加一个后续功能** —— 模板末尾列的"还能加什么"，一次挑一个

## 怎么贡献（把 🚧 变成 ✅）

你按某个模板跑通了，可以回来改这个目录：

1. 把模板顶部 frontmatter 的 `status: 草稿` 改成 `status: 已跑通`
2. 在模板末尾加一段「实测记录」，写清楚：
   - 你用的什么工具（CodeBuddy Code 版本号 / WorkBuddy / 其他）
   - 第一次跑有没有卡住，卡在哪
   - 你对提示词做了哪些改动（贴出来）
   - 最后做出来的东西大概多少行代码
3. 同时更新本文件里那张清单表的状态列

> 这份教程的价值，来自"真的有人跑过"，不是"写得像跑过"。
