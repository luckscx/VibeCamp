# 模板 · 待办清单

> ⚠️ **状态：草稿**。提示词尚未实机跑通，请以实际结果为准。

## 一句话描述

一个网页版待办清单：加任务、勾选完成、删任务，数据存本地。

## 为什么拿它当第一个应用

它比记账本还简单，但**麻雀虽小五脏俱全** —— 增删改查（CRUD）四件事它全占：

| 操作 | 对应 |
|---|---|
| 加一条 | Create |
| 看到列表 | Read |
| 勾选 / 改内容 | Update |
| 删一条 | Delete |

绝大多数小应用，拆到底都是这四件事的组合。待办清单做通了，
后面做笔记、做清单、做收藏夹，套路是一样的。

## 完整需求

```markdown
# 待办清单

## 一句话
我要做一个待办清单网页，用来记今天要做的事。

## 给谁用
我自己。

## 怎么用
1. 打开页面，看到一个输入框和下面的任务列表
2. 我在输入框打字，回车，任务加到列表里
3. 点任务左边的方框，任务变灰 + 加删除线，表示完成
4. 点任务右边的 ×，删掉这条
5. 底部显示"还剩 N 条未完成"

## 必须有的功能
1. 输入框回车添加任务
2. 勾选标记完成，视觉上明显区分（灰色 + 删除线）
3. 删除单条任务
4. 底部统计未完成数量
5. 数据存浏览器本地，关掉再开还在

## 明确不要的
1. 不要登录、云端同步
2. 不要分类 / 标签 / 优先级
3. 不要截止日期、提醒通知
4. 不要子任务
5. 不要手机 App
6. 不要拖拽排序（第一版不做）
7. 不要"已完成"折叠展开（第一版全列出来）

## 风格参考
- 白底，卡片式，圆角 8px
- 完成的任务文字变 #999，加删除线
- 删除按钮平时淡一点，鼠标移上去才变明显

## 技术偏好
- 单个 HTML 文件，双击就能用
- 数据存 localStorage
```

## 建议的第一句话

```markdown
我要做一个待办清单网页，完整需求见上。

在动手之前，请先问我 5 个问题。特别确认这两点：
- 空内容按回车会发生什么（应该什么都不做，而不是加一条空白任务）
- 刷新页面后任务的完成状态会不会保留

一次问完，我逐条回答。问完等我确认再写代码。

代码要求：
- 单个 HTML 文件，双击就能用，不需要命令行构建
- 中文注释
- 我是零基础

做完请告诉我：
1. 怎么打开
2. 我该看到什么
3. 做哪几步能验证数据存下来了
```

## 验收点

- [ ] 打开能看到输入框和空列表（或"暂无任务"提示）
- [ ] 输入"买牛奶"回车，出现在列表里
- [ ] **什么都不输入直接回车，不会加一条空白任务**
- [ ] 点方框，任务变灰 + 删除线；再点一次，变回未完成
- [ ] 底部计数正确：加了 3 条完成 1 条，显示"还剩 2 条未完成"
- [ ] 点 × 删掉一条，列表和计数都更新
- [ ] **关掉浏览器再打开**，任务和完成状态都还在

> 加粗那两条是最常漏的边界情况：
> 「空输入」和「完成状态的持久化」。AI 第一版经常只做通理想路径。

## 做完之后还能加什么

1. 一键清除全部已完成
2. 编辑任务内容（双击变输入框）
3. 筛选：全部 / 未完成 / 已完成
4. 分类标签
5. 截止日期 + 逾期标红

## 这个模板教了什么

- **边界情况要在提示词里就点名** —— "空输入按回车"这种事，
  你不问，AI 不会主动处理；等你自己踩到，又要多一轮对话
- **CRUD 是所有小应用的骨架** —— 这个做通了，
  你会发现"做个笔记应用"其实就是把"任务"换成"笔记"、去掉"完成"状态
