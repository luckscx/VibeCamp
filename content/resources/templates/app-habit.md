# 模板 · 习惯打卡

> ⚠️ **状态：草稿**。提示词尚未实机跑通，请以实际结果为准。

## 一句话描述

一个习惯打卡页面：列出想坚持的习惯，每天点一下打卡，显示连续坚持了多少天。

## 为什么它比待办清单多一点意思

多了两个概念，都是小应用里很常见的：

1. **日期** —— 数据要跟"哪一天"绑定，不能只记个布尔值
2. **连续天数** —— 要基于历史数据算出结果，不是简单存个数字

「连续天数」这点特别值得练：它**不该存起来**，而该算出来。
存起来就会出现"日期断了但数字还在涨"的 bug。

## 完整需求

```markdown
# 习惯打卡

## 一句话
我要做一个习惯打卡网页，用来记录每天坚持了哪些习惯。

## 给谁用
我自己。

## 怎么用
1. 打开页面，看到几个习惯卡片，每个上面有"今日打卡"按钮和连续天数
2. 点某个习惯的"打卡"，按钮变成已完成状态，连续天数 +1
3. 第二天再打开，按钮恢复成未打卡，可以再打
4. 每个习惯显示最近 7 天的打卡情况（小方块，打卡了就填色）

## 必须有的功能
1. 预置几个习惯（早起、运动、读书），能添加新习惯
2. 每个习惯每天可打卡一次，当天已打卡就不能重复打
3. 显示"连续坚持 N 天"
4. 每个习惯显示最近 7 天的格子，打了卡的填色
5. 数据存浏览器本地，关掉再开还在

## 明确不要的
1. 不要登录、云端同步
2. 不要提醒通知
3. 不要数据统计图表
4. 不要手机 App
5. 不要删除习惯的功能（第一版不做，避免误删历史）

## 风格参考
- 白底，卡片式，圆角
- 打卡完成用绿色 #10b981
- 7 天格子用小方块，未打卡是浅灰 #e5e7eb

## 技术偏好
- 单个 HTML 文件，双击就能用
- 数据存 localStorage
- 日期用本地日期（不要用 UTC，避免跨时区算错天）
```

## 建议的第一句话

```markdown
我要做一个习惯打卡网页，完整需求见上。

在动手之前，请先问我 5 个问题。特别确认这两点：
- "连续天数"是每次打开时基于日期算出来的，还是存一个数字？
  （我的想法是算出来，存数字的话断签了会出错，你觉得呢）
- 判断"是不是同一天"用什么标准？跨时区怎么办？

一次问完，我逐条回答。问完等我确认再写代码。

代码要求：
- 单个 HTML 文件，双击就能用
- 中文注释
- 我是零基础

做完请告诉我怎么打开、该看到什么、怎么验证连续天数是对的。
```

## 验收点

- [ ] 打开能看到预置的几个习惯卡片
- [ ] 点"打卡"，按钮变已完成，连续天数变成 1
- [ ] **当天再点一次，不会变成 2**（一天只能打一次）
- [ ] 7 天格子里，今天那格填色了
- [ ] 关掉浏览器再打开，打卡状态和连续天数还在
- [ ] 能添加新习惯，新习惯的连续天数是 0

**验证连续天数算得对不对**（这条需要动点手脚）：

> 让 AI 加一个临时功能：把"今天"当作明天来算（或者手动改一下浏览器里的日期数据），
> 看看连续天数会不会断。测完让它把临时功能删掉。
>
> 更简单的方法：问 AI 一句
> 「如果我昨天没打卡，今天打开，连续天数应该是多少？你的代码是怎么保证这一点的？」
> 让它自己解释，你听逻辑通不通。

## 做完之后还能加什么

1. 删除习惯（带二次确认）
2. 打卡时的鼓励动效
3. 月度热力图（像 GitHub 贡献图那样）
4. 最长连续记录
5. 导出打卡数据

## 这个模板教了什么

- **"算出来"还是"存起来"是个真问题** —— 连续天数存起来最简单，
  但断签时会错。这类"派生数据"应该每次算，别存
- **主动问 AI"你的代码怎么保证 X"** —— 这是零基础也能做的验证：
  你不会读代码，但你能听懂解释。逻辑讲不通，多半就有问题
