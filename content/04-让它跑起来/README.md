# 第 4 章 · 让它跑起来

> **核心章。** 从"AI 说做完了"到"我真的看到它跑起来了"。

## 这一章要解决的问题

- AI 说"已完成"，但不知道跑在哪、怎么打开
- 看到效果不满意，不知道怎么提修改
- 越改越乱

## 大纲

### 4.1 迭代循环（最重要的一张图）
```
描述需求 → AI 做 → 打开看效果 → 提一个具体修改 → 回到"AI 做"
                        ↑                              │
                        └──────────────────────────────┘
```
**关键：一次只提一个修改。** 这是小白最容易违反、代价最高的一条。

### 4.2 怎么"打开看效果"
- **验收点**：能说出一个 URL（通常是 `http://localhost:xxxx`）
- ❌ 如果你不知道该打开哪个地址 —— **直接问 AI**：
  ```
  做完了。请告诉我：
  1. 我该打开哪个网址看效果
  2. 我该点哪里、会看到什么
  ```

### 4.3 怎么提修改（对比）
| ❌ 这样说 | ✅ 这样说 |
|---|---|
| "不好看" | "标题字号调大到 24px，颜色改成深灰 #333" |
| "不好玩" | "第一关太难了，前 3 波敌人从 5 个减到 2 个" |
| "有 bug" | "点开始按钮后画面没反应，控制台报 `xxx is not defined`" |
| "再改改" | "把结算面板从右侧移到屏幕中间" |

**原则：给现象，不给评价。**

### 4.4 报错了怎么贴给 AI
```
运行时报错了，错误信息：
（把整段红色文字复制过来）

我的操作是：（你点了什么）
我期望看到：（应该发生什么）
实际看到：（发生了什么）
```
→ 更多见 [05-排错](../05-排错/README.md)

### 4.5 防失忆：建立外部记忆
**这是本章最容易被忽略、但最重要的一节。**

CodeBuddy 会话**只在本地，不支持跨设备同步**，且上下文会满、满了会压缩。

三个保命文件：
| 文件 | 放哪 | 写什么 |
|---|---|---|
| `CODEBUDDY.md`（或 `.codebuddy/CODEBUDDY.md`） | 项目根目录 | 项目长期约定（技术栈、风格、不要做什么） |
| `PROGRESS.md` | 项目根目录 | 当前进度、下一步、已知问题 |
| `~/.codebuddy/CODEBUDDY.md` | 用户目录 | 个人偏好（中文回复、详细程度等） |

**CodeBuddy 怎么找记忆**（已核实）：从当前目录**向上递归到根目录**，读取沿途所有 `CODEBUDDY.md` / `CODEBUDDY.local.md`。子目录下的 `CODEBUDDY.md` 不会在启动时加载，只有读到那个子树的文件时才加载。

**用 `@` 导入其他文件**（最大递归 5 层）：
```markdown
查看 @README 了解项目概述，@package.json 了解可用的 npm 命令。

# 附加说明
- Git 工作流程：@docs/git-instructions.md
- 个人偏好：@~/.codebuddy/my-project-instructions.md
```
> 把个人偏好放在用户目录并用 `@` 导入，团队共享和个人定制就分开了。

**项目大了用 `.codebuddy/rules/`**（已核实）：
```
.codebuddy/
├── CODEBUDDY.md      # 主指令
└── rules/
    ├── code-style.md
    ├── testing.md
    └── security.md
```
规则文件支持 frontmatter 控制：
```markdown
---
alwaysApply: false
paths: src/api/**/*.ts
---
# API 开发规则
- 所有端点必须包含输入验证
```
`alwaysApply: true`（默认）= 始终注入；`false` + `paths` = 只在操作匹配文件时触发。

**CODEBUDDY.md 该写什么**（官方明确给了对照表）：

| ✅ 应该写 | ❌ 不应该写 |
|---|---|
| AI 猜不到的命令 | 读代码就能搞清楚的东西 |
| 和默认习惯不同的代码风格 | 标准的语言约定 |
| 测试说明和首选的测试运行器 | 详细的 API 文档（放链接就行） |
| 仓库规范（分支命名、MR 约定） | 经常变化的信息 |
| 项目特有的架构决策 | 长篇大论的解释或教程 |
| 开发环境的坑（必需的环境变量等） | 逐文件的代码描述 |
| 常见陷阱或不明显的行为 | "写干净的代码"之类的废话 |

> ⚠️ **官方提醒**：CODEBUDDY.md 太长的话，AI 会忽略一半，因为重要规则被淹没在噪音里了。
> **狠心精简** —— 没有这条规则它也做对了，就删掉。

生成/查看：`/init` 生成，`/memory` 查看已加载的记忆文件。

**救命命令：**
```
> /compact     压缩上下文（长会话必做）
> /compact 只保留 API 相关的改动    ← 可以带指令精细控制
> /clear       开全新会话（改不动了就用这个）
> /cost        看花了多少
```

**可以指定压缩规则** —— 写在 CODEBUDDY.md 里：
> "压缩时，始终保留修改过的文件列表和测试命令"

会话恢复（已核实）：
```bash
codebuddy --resume              # 恢复最近会话
codebuddy --resume <session-id> # 恢复指定会话
codebuddy --continue            # 继续最近对话
```

### 4.6 官方给的中断与回退手段（比"撤销"更好用）

| 操作 | 作用 |
|---|---|
| `Esc` | **中途打断它在做的事**。上下文保留，你可以重新引导 |
| `Esc + Esc` 或 `/rewind` | 打开**回退菜单**，恢复到之前的对话和代码状态 |
| "撤销刚才的改动" | 让它回滚修改 |
| `/clear` | 不相关任务之间清空上下文 |

**检查点（Checkpoint）** —— 它每次改东西前都会自动存一个：
- 连按两次 `Esc` 或 `/rewind` 打开菜单
- 可以只恢复对话（保留代码）、只恢复代码（保留对话）、或两者都恢复
- **跨会话持久化** —— 关掉终端回来还能回退

> ⚠️ 官方文档警告：**检查点只追踪它做的改动，不追踪外部进程。它不能替代 git。**

**官方判据（比"3 轮"更准）**：
> "如果同一个问题你已经纠正了**两次**还是不对，说明上下文里已经堆满了失败的尝试。
> 这时候运行 `/clear`，用一个更清晰的提示重新开始，把学到的东西融入进去。"

### 4.7 卡住了怎么办（止损三板斧）
1. **回滚** —— `Esc`/`/rewind`，或让它"撤销刚才的改动"
2. **/clear** —— 清上下文重开（记忆文件还在，不会丢），**带上这次学到的东西重写提示**
3. **新开目录** —— 从干净状态重做，只把需求文件带过去

### 4.8 五个官方点名的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **无关上下文干扰** | 中途问了别的事，回来后它开始犯迷糊 | 任务切换时 `/clear` |
| **反复纠正** | 纠正 → 还错 → 再纠正 | 纠正两次不行就 `/clear` 重来 |
| **CODEBUDDY.md 写太多** | 它忽略了一半规则 | 狠心精简 |
| **只信任不验证** | 代码看着对，边缘情况没处理 | 始终提供验证手段 |
| **无边界的探索** | 让它"调查一下"，它读了几百个文件 | 缩小范围，或用子代理 |

## 验收点

- [ ] 能独立打开自己做出来的东西
- [ ] 提修改时用"现象"而不是"评价"
- [ ] 项目里有 `PROGRESS.md`，且更新过至少一次
- [ ] 知道上下文满了该敲什么
- [ ] 知道 `Esc` 能打断它、`Esc+Esc` 能回退
