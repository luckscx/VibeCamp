# 第 4 章 · 让它跑起来

> **核心章。** 从"AI 说做完了"到"我真的看到它跑起来了"。

## 这一章要解决的问题

- AI 说"已完成"，但不知道跑在哪、怎么打开
- 看到效果不满意，不知道怎么提修改
- 越改越乱

## 大纲

### 4.1 迭代循环（最重要的一张图）
```
描述需求 → AI 做 → 打开看效果 → 提一个具体修改 → 回到"AI 做"
                        ↑                              │
                        └──────────────────────────────┘
```
**关键：一次只提一个修改。** 这是小白最容易违反、代价最高的一条。

### 4.2 怎么"打开看效果"

#### 示例 1：让它给你一份验收清单

**你输入：**

> 做完了。请告诉我：
> 1. 我该打开哪个网址看效果（具体命令 + 完整地址）
> 2. 我该点哪里、会看到什么
> 3. 现在有哪些功能是能试的

**AI 可能会回：**

> 1. 终端运行 `npm run dev`，然后浏览器打开 http://localhost:5173
> 2. 你会看到：白色背景，中间一个 800×600 的浅灰网格，一条蛇在移动
> 3. 现在能试：
>    - 方向键控制蛇的移动
>    - 吃到红点加分，蛇变长
>    - 空格键暂停

**为什么不要问"做好了吗"**：问"做好了吗"，它大概率回"做好了"。
问**具体怎么验收**，你就拿到一份**验收清单** ——
照着走一遍，哪里不对立刻知道。

**验收点**：你能说出三件事 —— 打开地址、该看到什么、能试哪些功能。

#### 示例 2：页面打不开，按顺序排查

每一步都让 AI 给**具体的检查命令**，别自己瞎试：

| 步骤 | 你问 AI | 期望拿到 |
|---|---|---|
| 1 | "服务起来了吗？怎么看它在不在跑？" | 一条检查命令 |
| 2 | "终端显示的是哪个端口？" | 一个具体数字，如 5173 |
| 3 | "我打开 localhost:5173 是白屏，可能是什么原因？" | 常见原因清单 |

> ❌ 不要只说"我刷新了好几次还是白屏" —— 这句话对 AI 没有任何信息量。
> ✅ 把**检查命令的输出**贴给它，它才能判断。

### 4.3 怎么提修改（对比）
| ❌ 这样说 | ✅ 这样说 | 为什么后者好 |
|---|---|---|
| "不好看" | "标题字号调大到 24px，颜色改成深灰 #333" | AI 没有你的审美，形容词是空词 |
| "不好玩" | "第一关太难了，前 3 波敌人从 5 个减到 2 个" | 给了可量化的调整方向 |
| "有 bug" | "点开始按钮后画面没反应，控制台报 `xxx is not defined`" | 有现象 + 有报错，不用它猜 |
| "再改改" | "把结算面板从右侧移到屏幕中间" | 明确了改什么、改成什么 |

**原则：给现象，不给评价。**

#### 示例 3：一轮完整的修改对话

**你输入（第 1 轮）：**

> 蛇移动得太快了，一秒钟就撞墙。
> 把初始速度降到现在的三分之一，每吃 5 个食物提速一档，最高不超过现在的速度。

**AI 回：**

> 已调整。初始刷新间隔从 100ms 改为 300ms，
> 每吃 5 个食物减 20ms，最快不低于 100ms。请刷新页面查看。

**你去刷新，试了一遍。**

**你输入（第 2 轮）：**

> 速度合适了。但发现一个新问题：撞墙后游戏直接结束了，
> 我希望显示"游戏结束"和最终得分，然后按空格重新开始。
> 只改这一处，别的不要动。

**AI 回：**

> 已添加结束画面，显示最终得分和"按空格重新开始"提示。请刷新查看。

**这几轮好在哪**：
- 每轮**只提一件事**，出问题立刻知道是谁的锅
- 第 2 轮加了"**只改这一处，别的不要动**"—— 防止它顺手改别的
- 每轮都以"**请刷新查看**"结束，形成闭环

> ⚠️ 如果你发现自己在同一处改了 3 轮还没对 —— **停**。
> 这不是 AI 的问题，是**需求没说清**。回第 3 章重新描述。

#### 示例 4：一次提五个要求，会发生什么

这是"一次只提一个"这条原则的反面教材。

**你输入（❌ 反面示范）：**

> 帮我改一下：
> 1. 蛇的颜色改成蓝色
> 2. 背景加个网格线
> 3. 速度再快一点
> 4. 加个音效
> 5. 右上角显示最高分

**大概率发生的事**：

- 它五个都做了，但**其中一两个做得不对**（比如音效在某些浏览器不响）
- 你说"第 4 个不对"，它改第 4 个，**顺手把第 2 个改坏了**
- 你说"第 2 个也坏了"，它修第 2 个，**第 3 个的速度又变回去了**
- 三轮之后，你在五个问题之间来回跳，谁都记不清哪个是最初的版本

**✅ 换成这样：**

> 先只改一个：蛇的颜色改成蓝色 #3b82f6。
> 别的都不要动，改完告诉我。

验收过了，再提第二个。**五个要求 = 五轮对话，但每轮十秒就验收完。**

**为什么这样反而更快**：

| | 一次提五个 | 一次提一个 |
|---|---|---|
| 出问题时的定位 | 五个里找，不知道是谁 | 就是刚提的那个 |
| 修好要几轮 | 常常 3 轮以上打转 | 通常 1 轮 |
| 顺手改坏别处的概率 | 高 | 低 |
| 你的心理负担 | 越改越慌 | 每次都是小胜 |

> 💡 **唯一的例外**：如果五个要求之间**强相关**（比如"把配色整体换成蓝色系"），
> 那就一次说清 —— 拆开反而会因为上下文不同导致配色不统一。

#### 示例 5：改到一半发现方向错了，怎么刹车

**场景**：你让它做一个记账本，做到一半你发现 ——
其实你更想要的是"能拍照识别小票"的版本，现在这个手动记账的方向不对。

**❌ 常见反应（代价最高）：**

> 那个……其实我想要的是拍照识别，能不能在这个基础上加？

问题在于：已经写好的手动记账逻辑会变成**包袱**。
AI 会试图在旧结构上"加"功能，结果做出来一个两头不靠的东西。

**✅ 正确的刹车：**

> 停一下，先不要改代码。
>
> 我发现需求搞错了：我真正想要的是拍照识别小票，
> 不是手动记账。刚才做的手动记账部分先保留，别动。
>
> 请帮我确认三件事：
> 1. 在现有基础上加拍照识别，和推倒重做，哪个更合理？为什么？
> 2. 如果推倒重做，现有的哪些代码能复用？
> 3. 你现在建议怎么做？
>
> 先给我方案，我确认了再动手。

**为什么这样好**：

- **"先不要改代码"** —— 叫停了它在错误方向上继续投入
- **"先保留，别动"** —— 明确不会白干，你也不用心疼已投入的
- **让它先给方案** —— 你拿到的是分析，不是一堆改完的代码
- **你掌握决定权** —— 加还是重做，你说了算，不是它替你决定

> 💡 **判断该继续还是重来的简单标准**：
> 如果新需求**推翻了原来的核心逻辑**（手动记账 → 拍照识别），重来。
> 如果只是在原来基础上**加东西**（记账本加个统计图表），继续。
>
> 拿不准就问它："在现有基础上改，和推倒重做，哪个更合理？"

### 4.4 报错了怎么贴给 AI
```
运行时报错了，错误信息：
（把整段红色文字复制过来）

我的操作是：（你点了什么）
我期望看到：（应该发生什么）
实际看到：（发生了什么）
```
→ 更多见 [05-排错](../05-排错/README.md)

### 4.5 防失忆：建立外部记忆
**这是本章最容易被忽略、但最重要的一节。**

CodeBuddy 会话**只在本地，不支持跨设备同步**，且上下文会满、满了会压缩。

三个保命文件：
| 文件 | 放哪 | 写什么 |
|---|---|---|
| `CODEBUDDY.md`（或 `.codebuddy/CODEBUDDY.md`） | 项目根目录 | 项目长期约定（技术栈、风格、不要做什么） |
| `PROGRESS.md` | 项目根目录 | 当前进度、下一步、已知问题 |
| `~/.codebuddy/CODEBUDDY.md` | 用户目录 | 个人偏好（中文回复、详细程度等） |

**CodeBuddy 怎么找记忆**（已核实）：从当前目录**向上递归到根目录**，读取沿途所有 `CODEBUDDY.md` / `CODEBUDDY.local.md`。子目录下的 `CODEBUDDY.md` 不会在启动时加载，只有读到那个子树的文件时才加载。

**用 `@` 导入其他文件**（最大递归 5 层）：
```markdown
查看 @README 了解项目概述，@package.json 了解可用的 npm 命令。

# 附加说明
- Git 工作流程：@docs/git-instructions.md
- 个人偏好：@~/.codebuddy/my-project-instructions.md
```
> 把个人偏好放在用户目录并用 `@` 导入，团队共享和个人定制就分开了。

**项目大了用 `.codebuddy/rules/`**（已核实）：
```
.codebuddy/
├── CODEBUDDY.md      # 主指令
└── rules/
    ├── code-style.md
    ├── testing.md
    └── security.md
```
规则文件支持 frontmatter 控制：
```markdown
---
alwaysApply: false
paths: src/api/**/*.ts
---
# API 开发规则
- 所有端点必须包含输入验证
```
`alwaysApply: true`（默认）= 始终注入；`false` + `paths` = 只在操作匹配文件时触发。

**CODEBUDDY.md 该写什么**（官方明确给了对照表）：

| ✅ 应该写 | ❌ 不应该写 |
|---|---|
| AI 猜不到的命令 | 读代码就能搞清楚的东西 |
| 和默认习惯不同的代码风格 | 标准的语言约定 |
| 测试说明和首选的测试运行器 | 详细的 API 文档（放链接就行） |
| 仓库规范（分支命名、MR 约定） | 经常变化的信息 |
| 项目特有的架构决策 | 长篇大论的解释或教程 |
| 开发环境的坑（必需的环境变量等） | 逐文件的代码描述 |
| 常见陷阱或不明显的行为 | "写干净的代码"之类的废话 |

> ⚠️ **官方提醒**：CODEBUDDY.md 太长的话，AI 会忽略一半，因为重要规则被淹没在噪音里了。
> **狠心精简** —— 没有这条规则它也做对了，就删掉。

生成/查看：`/init` 生成，`/memory` 查看已加载的记忆文件。

**救命命令：**
```
> /compact     压缩上下文（长会话必做）
> /compact 只保留 API 相关的改动    ← 可以带指令精细控制
> /clear       开全新会话（改不动了就用这个）
> /cost        看花了多少
```

**可以指定压缩规则** —— 写在 CODEBUDDY.md 里：
> "压缩时，始终保留修改过的文件列表和测试命令"

会话恢复（已核实）：
```bash
codebuddy --resume              # 恢复最近会话
codebuddy --resume <session-id> # 恢复指定会话
codebuddy --continue            # 继续最近对话
```

### 4.6 官方给的中断与回退手段（比"撤销"更好用）

| 操作 | 作用 |
|---|---|
| `Esc` | **中途打断它在做的事**。上下文保留，你可以重新引导 |
| `Esc + Esc` 或 `/rewind` | 打开**回退菜单**，恢复到之前的对话和代码状态 |
| "撤销刚才的改动" | 让它回滚修改 |
| `/clear` | 不相关任务之间清空上下文 |

**检查点（Checkpoint）** —— 它每次改东西前都会自动存一个：
- 连按两次 `Esc` 或 `/rewind` 打开菜单
- 可以只恢复对话（保留代码）、只恢复代码（保留对话）、或两者都恢复
- **跨会话持久化** —— 关掉终端回来还能回退

> ⚠️ 官方文档警告：**检查点只追踪它做的改动，不追踪外部进程。它不能替代 git。**

**官方判据（比"3 轮"更准）**：
> "如果同一个问题你已经纠正了**两次**还是不对，说明上下文里已经堆满了失败的尝试。
> 这时候运行 `/clear`，用一个更清晰的提示重新开始，把学到的东西融入进去。"

### 4.7 卡住了怎么办（止损三板斧）
1. **回滚** —— `Esc`/`/rewind`，或让它"撤销刚才的改动"
2. **/clear** —— 清上下文重开（记忆文件还在，不会丢），**带上这次学到的东西重写提示**
3. **新开目录** —— 从干净状态重做，只把需求文件带过去

### 4.8 五个官方点名的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **无关上下文干扰** | 中途问了别的事，回来后它开始犯迷糊 | 任务切换时 `/clear` |
| **反复纠正** | 纠正 → 还错 → 再纠正 | 纠正两次不行就 `/clear` 重来 |
| **CODEBUDDY.md 写太多** | 它忽略了一半规则 | 狠心精简 |
| **只信任不验证** | 代码看着对，边缘情况没处理 | 始终提供验证手段 |
| **无边界的探索** | 让它"调查一下"，它读了几百个文件 | 缩小范围，或用子代理 |

## 验收点

- [ ] 能独立打开自己做出来的东西
- [ ] 提修改时用"现象"而不是"评价"
- [ ] 项目里有 `PROGRESS.md`，且更新过至少一次
- [ ] 知道上下文满了该敲什么
- [ ] 知道 `Esc` 能打断它、`Esc+Esc` 能回退
