# 第 4 章 · 让它跑起来

> **核心章。** 从"AI 说做完了"到"我真的看到它跑起来了"。

## 这一章要解决的问题

- AI 说"已完成"，但不知道跑在哪、怎么打开
- 看到效果不满意，不知道怎么提修改
- 越改越乱

## 大纲

### 4.1 迭代循环（最重要的一张图）
```
描述需求 → AI 做 → 打开看效果 → 提一个具体修改 → 回到"AI 做"
                        ↑                              │
                        └──────────────────────────────┘
```
**关键：一次只提一个修改。** 这是小白最容易违反、代价最高的一条。

### 4.2 怎么"打开看效果"
- **验收点**：能说出一个 URL（通常是 `http://localhost:xxxx`）
- ❌ 如果你不知道该打开哪个地址 —— **直接问 AI**：
  ```
  做完了。请告诉我：
  1. 我该打开哪个网址看效果
  2. 我该点哪里、会看到什么
  ```

### 4.3 怎么提修改（对比）
| ❌ 这样说 | ✅ 这样说 |
|---|---|
| "不好看" | "标题字号调大到 24px，颜色改成深灰 #333" |
| "不好玩" | "第一关太难了，前 3 波敌人从 5 个减到 2 个" |
| "有 bug" | "点开始按钮后画面没反应，控制台报 `xxx is not defined`" |
| "再改改" | "把结算面板从右侧移到屏幕中间" |

**原则：给现象，不给评价。**

### 4.4 报错了怎么贴给 AI
```
运行时报错了，错误信息：
（把整段红色文字复制过来）

我的操作是：（你点了什么）
我期望看到：（应该发生什么）
实际看到：（发生了什么）
```
→ 更多见 [05-排错](../05-排错/README.md)

### 4.5 防失忆：建立外部记忆
**这是本章最容易被忽略、但最重要的一节。**

CodeBuddy 会话**只在本地，不支持跨设备同步**，且上下文会满、满了会压缩。

三个保命文件：
| 文件 | 放哪 | 写什么 |
|---|---|---|
| `CODEBUDDY.md` | 项目根目录 | 项目长期约定（技术栈、风格、不要做什么） |
| `PROGRESS.md` | 项目根目录 | 当前进度、下一步、已知问题 |
| `~/.codebuddy/CODEBUDDY.md` | 用户目录 | 个人偏好（中文回复、详细程度等） |

记忆文件格式（已核实）：
```markdown
## CodeBuddy Added Memories
- 用中文回复
- 前端用 Tailwind，不要写原生 CSS
```
支持 `@import ./docs/team-conventions.md` 引用外部文件。

**救命命令：**
```
> /compact     压缩上下文（长会话必做）
> /clear       开全新会话（改不动了就用这个）
> /cost        看花了多少
```

会话恢复（已核实）：
```bash
codebuddy --resume              # 恢复最近会话
codebuddy --resume <session-id> # 恢复指定会话
codebuddy --continue            # 继续最近对话
```

### 4.6 卡住了怎么办（止损三板斧）
1. **回滚** —— 让 AI 撤销刚才那次改动
2. **/clear** —— 清上下文重开（记忆文件还在，不会丢）
3. **新开目录** —— 从干净状态重做，只把需求文件带过去

## 验收点

- [ ] 能独立打开自己做出来的东西
- [ ] 提修改时用"现象"而不是"评价"
- [ ] 项目里有 `PROGRESS.md`，且更新过至少一次
- [ ] 知道上下文满了该敲什么
