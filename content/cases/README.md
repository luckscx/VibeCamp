# 真实案例

> 这些案例**不是编的**，全部来自本机真实项目的 git 历史。
> 每个案例都标注了来源仓库和 commit 号，你可以自己翻出来对照看。

## 为什么要有这个

教程里的示例是为了讲清一个点而**构造**的，简洁但理想化。
真实项目里的事情要 messy 得多：

- 一个 bug 要改三轮才干净
- 改完一处发现另一处有同样的毛病
- AI 给的代码能跑，但体验很糟

**看别人真实踩过的坑，比看十个正确示范学得多。**

## 怎么自己找案例

你自己的项目也是素材。跑这些命令：

```bash
# 看所有提交
git log --oneline

# 只看修 bug 的
git log --oneline --grep="fix"

# 看某个 commit 改了什么
git show <commit号>

# 看某个文件的修改历史
git log -p -- <文件路径>
```

**找案例的三个标准**：
1. **有明确的前后对比** —— 改之前什么样、改之后什么样
2. **有 root cause** —— 不只是"修好了"，而是知道"为什么会坏"
3. **能抽象出通用教训** —— 换个项目也适用

> 💡 找不到好的？看看你的 commit 里有没有**连续几个都在改同一个地方** ——
> 那种"改了又改"的地方，往往藏着最好的案例。
