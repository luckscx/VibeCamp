# 操作示例规范

每章必须包含**可直接照做的操作示例**，不能只讲道理。

## 一、示例的三种形态

### 1. 对话示例（最常用）

展示「你输入什么 → AI 回什么」。必须包含**真实回应的形态**，不能只写"AI 会帮你做好"。

```markdown
**你说：**

> 做一个贪吃蛇游戏。

**AI 可能会回：**

> 好的，我先确认几个细节：
> 1. 用什么技术实现？网页版还是命令行？
> 2. 需要计分和最高分记录吗？
> ...
```

**要求**：
- 用 `>` 引用块区分「你说」和「AI 回」
- AI 的回应要**像真的** —— 包含它真会问的那些问题
- 标出"可能" —— AI 每次回的不完全一样，别写成唯一答案

### 2. 命令示例

```markdown
在终端里输入：

\`\`\`bash
node --version
\`\`\`

**你应该看到：**
\`\`\`
v20.11.0
\`\`\`

**如果看到 `command not found`** → 说明 Node 没装，回到 2.1 节。
```

**要求**：三段式 —— 输入 / 应该看到 / 不对怎么办

### 3. 正反对比示例

| ❌ 这样说 | ✅ 这样说 | 为什么 |
|---|---|---|
| ... | ... | ... |

**要求**：必须解释"为什么"，否则读者只会抄不会判断

### 4. 真实案例（长篇）

来自**真实项目 git 历史**的完整案例，放在 `content/cases/<案例名>/README.md`。

**frontmatter 必填**：

```yaml
---
title: 一句话概括这个案例
repo: 来源仓库名
commits: [abc1234, def5678]   # commit 号，可溯源
date: 2026-07-26 ~ 07-28
tags: [状态持久化, 边界情况, 多轮修复]
---
```

**正文结构**（七段式）：

1. **一句话** —— 这个案例讲了什么坑
2. **背景** —— 当时的需求是什么
3. **出了什么问题** —— 贴原始代码 + 实际后果
4. **怎么修的** —— 按 commit 顺序，每轮解决什么
5. **这个案例教了什么** —— 抽象成通用教训，3-4 条
6. **相关章节** —— 回链到主线章节

**要求**：
- **必须可溯源** —— 贴出真实 commit message 原文（英文可附中文翻译）
- **代码要真实** —— 从 `git show` 里复制，不要凭记忆重写
- **要抽象** —— 不能只讲"这个项目怎么修的"，要讲"你遇到同类问题怎么办"
- **配图优先** —— 有图能说清的就配，放 `cases/assets/`，引用写法：

  ```markdown
  ![起步阶段](../assets/起步阶段-家庭工作室.webp)
  ```

  注意是 `../` —— 因为写链接的文件在 `cases/xxx/` 下，图片在 `cases/assets/` 下

## 二、写作硬规则

1. **每段示例都要有"验收点"** —— 读者怎么知道自己做对了
2. **报错信息必须是真样本** —— 不许编造。没实测过就标 `待验证`
3. **命令必须给全** —— 包括 `cd` 到哪个目录
4. **不确定的地方明说** —— "AI 每次回的不完全一样，但大同小异"
5. **示例要可复制** —— 代码块里的提示词能直接粘走用
6. **案例必须可溯源** —— 写明仓库 + commit 号，代码从 `git show` 复制
7. **相对路径按"文件所在层级"算** —— 跑 `python3 scripts/export.py` 会自动校验

## 三、示例密度要求

| 章节类型 | 最少示例数 |
|---|---|
| 核心章（03、04） | 5 个以上 |
| 操作章（02、06） | 每个步骤 1 个 |
| 概念章（00、01） | 3 个以上 |
| 排错章（05） | 每个症状 1 个 |

## 四、相对路径怎么算（高频错误）

**基准是「写这个链接的文件所在的目录」，不是 content/ 根目录。**

| 你在写 | 要指向 | 正确写法 |
|---|---|---|
| `cases/xxx/README.md` | `cases/assets/a.webp` | `../assets/a.webp` |
| `cases/xxx/README.md` | `03-章/README.md` | `../../03-说清楚需求/README.md` |
| `03-章/README.md` | `resources/prompts/` | `../resources/prompts/` |
| `cases/README.md` | `cases/xxx/README.md` | `./xxx/README.md`（或 `xxx/README.md`） |

> 不确定就跑 `python3 scripts/export.py`，脚本**会自动校验所有相对链接**
> 并把失效的打出来。
