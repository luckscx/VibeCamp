# 第 5 章 · 排错：报错了怎么办

## 这一章要解决的问题

报错就慌，只会来回贴报错，越改越乱。

## 核心心法

> **报错不是失败，是 AI 最擅长处理的东西。**
> 真正危险的不是报错，是"改了 20 轮还是不对"却舍不得重来。

## 大纲

### 5.1 排错决策树
```
出错了
  │
  ├─ 页面打不开（白屏 / 连不上）
  │    └─ 服务没起来？端口被占？→ 看 5.2
  │
  ├─ 能打开，但某个功能点了没反应
  │    └─ 打开浏览器控制台（F12）看红色报错 → 整段复制给 AI
  │
  ├─ 报错信息 AI 看不懂 / 改了没用
  │    └─ 上下文已经乱了 → 用止损三板斧（5.4）
  │
  └─ 改了 3 轮以上还在同一个地方打转
       └─ 停下来，这是需求没说清，回第 3 章
```

### 5.2 常见症状速查表

| 症状 | 可能原因 | 第一动作 |
|---|---|---|
| 白屏 | 服务没起 / 端口错 | 问 AI："服务在哪个端口跑？" |
| `port already in use` | 端口被占 | 换端口或杀掉旧进程 |
| `command not found` | 工具没装 / PATH 问题 | 见第 2 章 2.3 |
| `Cannot find module xxx` | 依赖没装 | 让 AI 跑安装命令 |
| 改了代码页面没变 | 缓存 / 没热更新 | 硬刷新（Ctrl+Shift+R） |
| 本地能跑，别人打不开 | 只跑了本地服务 | 见第 6 章 |

### 5.3 怎么把报错贴给 AI（模板）

```
报错了。

【我做了什么】点了"开始游戏"按钮
【期望】进入游戏画面
【实际】页面卡住，控制台红色报错
【完整报错】
（整段复制，不要只截一行）

【相关文件】如果你知道是哪个文件，贴文件名
```

三个 **不要**：
- ❌ 不要只贴最后一行（前面的堆栈信息才是关键）
- ❌ 不要自己删改报错内容
- ❌ 不要说"还是不行"而不给新信息

### 5.4 止损三板斧（改不动了就用）

**重要：这不是认输，是专业做法。**

| 招式 | 什么时候用 | 怎么做 |
|---|---|---|
| **1. 打断** | 它跑偏了、在做你没要求的事 | 按 `Esc`，上下文保留，重新引导 |
| **2. 回退** | 刚改完就坏了 | `Esc+Esc` 或 `/rewind` 打开检查点菜单 |
| **3. /clear** | 纠正两次还不对 | 敲 `/clear`，**带上学到的东西重写提示** |
| **4. 新开目录** | 整个方向乱了 | 新建文件夹，只把 `BRIEF.md` 和 `PROGRESS.md` 带过去，重新 `/init` |

**官方判据：同一个问题纠正两次还不对 → 立刻 `/clear`。**

> 官方文档原话：
> "干净的会话配上更好的提示，几乎总是比不断追加纠正的长会话效果更好。"

### 5.5 让 AI 自查，而不是你盯着

**官方最强调的一点**：给它验证手段，让它自己检查。

```
不要只说"改好了吗"。要说：
1. 跑一遍 `npm run build`，把输出贴给我
2. 如果报错，找出根本原因修复，不要绕过
3. 修复后确认 build 通过
```

**验证不了的东西，别上线。**
