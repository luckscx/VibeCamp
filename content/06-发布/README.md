# 第 6 章 · 发布：让别人也能打开

## 这一章要解决的问题

> **本地能跑 ≠ 别人能打开。** 这是小白最常踩的最后一个坑。

## 大纲

### 6.1 先分清三件事

| 概念 | 白话 | 谁能看 |
|---|---|---|
| **本地预览** | 只有你电脑上能开 | 只有你 |
| **局域网** | 同一个 WiFi 下能开 | 同事/家人 |
| **公网部署** | 有个网址，谁都能开 | 所有人 |

**`http://localhost:3000` 发给别人，别人一定打不开。**

### 6.2 发布路径（由易到难）

| 路径 | 难度 | 适合 | 状态 |
|---|---|---|---|
| 静态托管（纯前端页面） | ⭐ | 小游戏、小工具 | 见 6.2.1 |
| 容器/服务器部署 | ⭐⭐⭐ | 需要后端、数据库 | 见 6.2.2 |

#### 6.2.1 路径 A：静态托管（纯前端，推荐先走这条）

**先判断你的项目是不是"纯前端"**。问 AI 一句：

> 我这个项目是纯前端吗？可以只靠静态文件托管吗？
> 有没有需要后端服务器或数据库的部分？

**判断标准**（对照看看）：

| 特征 | 纯前端 ✅ | 需要后端 ❌ |
|---|---|---|
| 数据存在浏览器 localStorage | ✅ | |
| 有登录注册、多用户数据共享 | | ❌ |
| 需要调用第三方 API 且密钥不能暴露 | | ❌ |
| 只是个网页游戏/工具/展示页 | ✅ | |
| 需要定时任务、发邮件 | | ❌ |

### 示例 1：先判断你的项目能不能"拖上去就行"

**问 AI 一句：**

```
> 我这个项目是纯前端吗？可以只靠静态文件托管吗？
> 有没有需要后端服务器或数据库的部分？
```

**AI 可能会回**（形态参考，措辞每次不同）：

> 看了下你的项目结构，是纯前端的：
> - 数据存在 localStorage，没有数据库
> - 没有服务端接口调用
> - 用的 Vite 构建，产物是 `dist/`
>
> 可以用静态托管。

**或者另一种情况：**

> 你这个有后端：`server/` 目录下有 Express 服务，
> 还连了 SQLite 数据库。静态托管不行，需要能跑 Node 的托管服务。

**验收点**：你得到了明确的"能"或"不能"，以及原因。
如果 AI 说得含糊，把上面那张对照表里的特征逐条问它。

### 示例 2：纯前端项目的发布流程

**第 1 步 —— 生成静态文件**

```
> 帮我把这个项目构建成可以直接托管的静态文件。
> 告诉我：构建命令是什么、产物在哪个目录。
```

**你应该看到（示例）：**

> 构建命令：`npm run build`
> 产物目录：`dist/`
> 里面包含：index.html、assets/（js 和 css）

**自己跑一遍：**
```bash
npm run build
```

**你应该看到：**
```
✓ built in 3.42s
dist/index.html                   0.46 kB
dist/assets/index-a1b2c3d4.css   12.34 kB
dist/assets/index-a1b2c3d4.js   143.21 kB
```

**验收点**：项目里出现了 `dist/` 目录，里面有 `index.html`。

> 这一步有个高频翻车点：构建成功 ≠ 部署后能跑。
> 所以必须走第 2 步。

**第 2 步 —— 本地先验证一遍产物**

```bash
npx serve dist
```

**你应该看到：**
```
   ┌───────────────────────────────────┐
   │                                   │
   │   Serving!                        │
   │                                   │
   │   - Local:    http://localhost:3000
```

浏览器打开这个地址，**确认真的是你想要的效果**。
> ⚠️ 别跳过这步。构建后的产物和开发模式可能有差异，
> 上线了才发现就晚了。

### 示例 3：上线后怎么确认"真的部署了"

这一步看着多余，但踩过的人都知道它值。

**第 3 步 —— 选平台上传**

把 `dist/` 整个目录拖上去即可。主流选择：

| 平台 | 怎么传 | 免费额度 |
|---|---|---|
| Vercel | 连 GitHub 仓库自动部署 | 个人免费 |
| Netlify | 拖 `dist/` 文件夹进去就行 | 有免费档 |
| GitHub Pages | 需要推到 gh-pages 分支 | 免费 |
| 腾讯云 COS / 阿里云 OSS | 对象存储 + 静态网站 | 有免费额度 |

**最省事的做法** —— 直接问 AI：

```
> 我的 dist/ 目录已经准备好了。
> 我是纯新手，推荐一个最简单的免费托管方式，
> 给我每一步的操作，并告诉我每步做完应该看到什么。
```

**第 4 步 —— 验收**

- [ ] 拿到一个 `https://` 开头的公网网址
- [ ] **关掉本地服务**，再打开这个网址 —— 还能打开才算真的部署了
- [ ] 用手机打开一遍（不是电脑）

> 💡 最后那条是关键：很多人以为部署成功了，
> 其实是本地服务还在跑，网址指向的还是自己电脑。

#### 6.2.2 路径 B：需要后端/数据库

这条路线复杂得多（要买服务器、配域名、配 HTTPS、配进程守护）。

**别自己摸索，直接让 AI 带你走：**

```
> 我这个项目需要后端（或数据库），不能纯静态托管。
> 请给我一个完整的部署方案：
> 1. 推荐什么服务（要便宜、适合新手）
> 2. 需要买什么、多少钱
> 3. 每一步的命令和验收标准
> 4. 可能会卡住的地方
```

**你应该坚持的三个要求**：
1. **要命令，不要描述** —— "配置 nginx" 这种话没用，要能复制粘贴的命令
2. **要验收标准** —— 每步做完该看到什么
3. **要回滚方案** —— 改坏了怎么恢复

> ⚠️ **安全提醒**：部署到公网前，务必确认代码里**没有**密钥、密码、API Key。
> 一旦推到公开仓库，就算删掉也会被爬走。

#### 6.2.3 免费额度和限制：别信教程，去问 AI

> ⚠️ **这一节故意不写具体数字。**
>
> 各平台的免费额度**两三个月就变一次**，写在教程里的数字很快就过期，
> 过期了还会误导你。所以这里教你怎么**当场查到准确信息**。

**直接这样问：**

```
> 我想把静态网站托管到免费平台。帮我查一下这几个平台当前的免费额度：
> Vercel、Netlify、GitHub Pages、Cloudflare Pages。
>
> 每个平台告诉我：
> 1. 免费档包含什么（流量、构建次数、带宽上限）
> 2. 超出之后会怎样（是停止服务还是收费）
> 3. 需不需要绑信用卡
> 4. 有没有需要特别注意的限制
>
> 请给出你现在查到的信息，并说明这些数字可能会变。
```

**为什么让 AI 查而不是自己搜**：

- 它会一次给你**结构化的对比**，不用你开五个网页
- 你能在同一轮对话里追问"那我这种情况该选哪个"
- 它会顺带告诉你限制条款里容易踩的坑

**但要注意**：AI 的知识也有截止日期。涉及钱和额度的事，
**最后去官网确认一眼**。让 AI 给你链接，你自己点开看。

**新手最该关心的三个限制**（这几个不太会变）：

| 限制 | 为什么重要 |
|---|---|
| **需不需要绑信用卡** | 很多"免费"平台要绑卡才给用，超量会自动扣费 |
| **超出后是停服还是收费** | 停服最安全，收费可能产生意外账单 |
| **流量上限** | 你的小游戏如果被大量转发，可能几天就用完月流量 |

> 💡 **给新手的建议**：第一个项目选**停服型**的免费平台。
> 就算被转发爆了，最坏结果是网站停一会儿，不会收到账单。

#### 6.2.4 自定义域名：让 AI 带你走

自有域名（比如 `www.你的名字.com`）不是必需的，
但如果你想让别人容易记住，可以加。

**顺序很重要：先把默认域名跑通，再加自定义域名。**
两个变量一起改，出问题你不知道怪谁。

```
> 我的网站已经能通过 https://xxx.vercel.app 访问了。
> 现在我想用我自己的域名 www.xxx.com 来访问它。
>
> 请告诉我：
> 1. 我需要去域名服务商那里做什么设置（给具体的值，比如 CNAME 填什么）
> 2. 平台这边要做什么设置
> 3. 设置完之后多久生效
> 4. 怎么验证是不是配好了
> 5. 如果配错了，怎么回滚
```

**三个必须问到的点**：

1. **给具体的值** —— "配置 DNS" 这种话没用。
   要的是"CNAME 记录，主机名填 `www`，值填 `cname.vercel-dns.com`"
2. **生效时间** —— DNS 生效可能要几分钟到 48 小时，
   不知道这点的话，你会以为自己配错了然后反复改
3. **怎么回滚** —— 改 DNS 有一定风险，先知道怎么恢复

> ⚠️ **HTTPS 证书**：大部分平台会**自动**签发证书，你不用管。
> 但要在平台的设置里确认打开了。用 HTTP 打开会被浏览器标记为"不安全"。

### 6.3 发布前检查清单

- [ ] 手机上打开过（不只是电脑上）
- [ ] 换一个浏览器打开过
- [ ] 关掉本地服务后，网址还能打开（证明真的部署了，不是本地）
- [ ] 页面标题、图标改成了自己的
- [ ] 没有把自己的密钥/密码写进代码

### 6.4 让 AI 帮你发布

```
我要把这个项目发布到公网，让别人能通过一个网址打开。
请告诉我：
1. 我这个项目属于哪种类型（纯前端 / 需要后端）
2. 推荐最简单的发布方式
3. 每一步我应该看到什么
```
